# Claude GitLab Bridge

This is a Python-based FastAPI proxy that bridges Anthropic SDK clients like `claude-code` with GitLab Duo's infrastructure, allowing you to use Anthropic AI models seamlessly via GitLab.

## How it works
The bridge listens locally for standard Anthropic API requests (e.g., `/v1/messages`). It intercepts these requests, flattens the multi-turn conversational payloads, and forwards them to the GitLab Duo Code Suggestions API. It then wraps the AI's response back into the standard Anthropic SSE streaming format so your terminal CLI accepts it flawlessly.

To ensure strict security and prevent CLI tools from incorrectly caching your GitLab credentials, the bridge manages your real **GitLab Personal Access Token (PAT)** internally via a `.env` file. You then define a custom, local **Proxy API Key** to connect Claude Code to the bridge.

## Prerequisites
- Python 3.8+
- A GitLab Personal Access Token (PAT) with the `api` scope.
- Access to GitLab Duo features (e.g., GitLab Ultimate/Pro) on your GitLab account.

## Installation & Setup

1. Create a virtual environment and install the dependencies:
   ```bash
   python -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```

2. Create your environment configuration file:
   ```bash
   cp .env.example .env
   ```

3. Open the `.env` file and configure your tokens:
   ```env
   # Your real GitLab Personal Access Token (PAT)
   GITLAB_PAT="glpat-YOUR_GITLAB_PAT"

   # A custom, secret key you create to authenticate Claude Code with this proxy
   PROXY_API_KEY="my-super-secret-proxy-key"
   ```

4. Start the bridge server:
   ```bash
   python main.py
   ```
   The server will run on `http://0.0.0.0:8001`.

## Running Claude Code

Open a **new** terminal window. Set the environment variables to point Claude Code to the local bridge, using the `PROXY_API_KEY` you defined in your `.env` file:

```bash
export ANTHROPIC_BASE_URL="http://localhost:8001"
export ANTHROPIC_API_KEY="my-super-secret-proxy-key"

# Start Claude Code
claude
```

*(Note: You can request specific models like `claude --model claude-opus-4-8` if needed. The bridge supports this string, though the actual model used will be managed by GitLab Duo's internal model routing).*

## Advanced Authentication (OAuth 2.0 Browser Login)
If you prefer not to use a static PAT in your `.env` file, you can configure an OAuth Application in GitLab to enable a browser login flow:
1. Go to your GitLab **User Settings -> Applications**.
2. Create an application with the `api` scope and **Redirect URI**: `http://localhost:8001/callback`.
3. Add `GITLAB_CLIENT_ID` and `GITLAB_CLIENT_SECRET` to your `.env` file.
4. Visit `http://localhost:8001/login` in your browser to authenticate.
5. You can then start Claude Code and use your `PROXY_API_KEY` normally.

## Limitations
- **Prompt Flattening:** The bridge flattens Anthropic's complex multi-turn message history, system prompts, and tool results into a single large string for GitLab.
- **Simulated Streaming:** GitLab Duo's REST API does not natively stream Anthropic SSE chunks. The bridge fetches the complete response and simulates streaming it back to the client.
- **Tool Use/Functions:** Native Anthropic tool/function calling logic generated by Claude Code may be partially stripped or simplified depending on GitLab Duo's underlying capabilities.
